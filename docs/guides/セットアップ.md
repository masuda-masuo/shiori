# セットアップ

## 前提

- Docker / Docker Compose
- （非公開リポジトリを索引する場合）リポジトリ読み取り権限のある GitHub トークン

## 手順

```bash
git clone https://github.com/<your-username>/shiori.git  # フォークまたはクローン元に読み替え
cd shiori
cp .env.example .env
# .env を編集:
#   SHIORI_REPOS=owner/name      （カンマ区切りで複数可）
#   GITHUB_TOKEN=ghp_xxx         （公開リポジトリのみなら空でも可）

# DB と MCP サーバーを起動（初回はイメージビルド）
docker compose up -d --build

# 索引を作成（初回は埋め込みモデルのダウンロードを含むため時間がかかる）
# private リポジトリを索引する場合は、事前に .env で認証の設定が必要
# （推奨: SHIORI_TOKEN_COMMAND による mcp-token モデル。scripts/run-shiori が
#   runtime/github-token に短命トークンを供給する。PAT なら GITHUB_TOKEN）
# 注意: --build を忘れるとコード修正が反映されない（docker compose run は自動再ビルドしないため）
docker compose run --build --rm ingest

```

`ingest` サービスは `command` を内蔵しているため引数不要で、`app` と同じ認証設定（短命トークン or PAT）を持つが、使い捨てジョブとして分離されている。GitHub App の秘密鍵をファイルで置く方式（旧 `secrets/`）は廃止した — 鍵は mcp-launcher の OS keystore から出さず、コンテナには短命トークンだけが届く（mcp-launcher の `docs/architecture/security-model.md` 参照）。

日常運用は `scripts/` のスクリプトに集約されている（Windows は `.bat`、WSL/Linux は `.sh`）:

| スクリプト | 役割 |
| --- | --- |
| `scripts/run-shiori` | トークン更新ループを起動し、app コンテナを build + 起動 |
| `scripts/stop-shiori` | トークン更新ループ・旧ホスト serve・app コンテナを停止 |
| `scripts/update` | `git pull` + イメージ再ビルド + app 再起動 |
| `scripts/ingest` | ワンショット同期（`--rebuild` などの引数はそのまま渡る） |
| `scripts/refresh-token` | 短命トークンを `runtime/github-token` に発行（run-shiori が内部で利用） |

2 回目以降の `ingest` は差分同期（docs はファイルハッシュ、issue/PR は `updated_at` カーソル）なので速い。

## 索引の更新（3 経路）

| 経路 | 用途 |
| --- | --- |
| `SHIORI_SYNC_INTERVAL_SECONDS` | serve プロセス内のバックグラウンド自動同期。ポーリング間隔を設定（例: 10 秒）。 |
| CLI `python -m shiori ingest` | 初回構築・cron 等のスケジュール実行（`docker compose run --build --rm ingest`） |

## 埋め込みモデルの変更

埋め込みモデルを変更した場合は全件再索引する:

```bash
docker compose run --build --rm ingest -- --rebuild
```


## MCP クライアントからの接続

MCP サーバーは streamable HTTP で `http://localhost:8765/mcp` に公開される。

例: Claude Code

```bash
claude mcp add --transport http shiori http://localhost:8765/mcp
```

コンテナを使わずローカルの Python で stdio 接続したい場合:

```bash
pip install -e .
DATABASE_URL=postgresql://shiori:shiori@localhost:5432/shiori \
  python -m shiori serve --transport stdio
```

（compose の `db` は 127.0.0.1:5432 に公開済み。Windows ホストの場合は
`SHIORI_DATA_DIR` にクローン先ディレクトリの指定が必要）

## 提供される MCP ツール

| ツール | 用途 |
| --- | --- |
| `shiori_search` | 意味＋キーワードのハイブリッド検索（統合入口）。まずこれを使う |
| `shiori_keyword_search` | 固有名詞・API 名・エラーコード等の厳密一致（補助ツール） |
| `shiori_list_tree` | 索引済みドキュメント＋コードファイルのパス一覧 |
| `shiori_read_file` | ファイル全文（または行範囲）の取得 |
| `shiori_read_issue` | issue / PR スレッド全体の取得 |
| `shiori_pr_changes` | PR の変更ファイルマップ（メタデータ）。head_sha と変更ファイル一覧 |
| `shiori_status` | 索引の鮮度と健全性の確認 |

## トラブルシューティング

- **`EMBEDDING_DIM=... but model produces ...`:** モデルと次元の組み合わせが不一致。`.env` の `EMBEDDING_DIM` をモデルの次元に合わせ、`ingest --rebuild` を実行。
- **検索が 0 件:** `ingest` が完了しているか、`SHIORI_REPOS` が正しいかを確認。
- **コード修正が反映されない:** `docker compose run` はイメージを自動再ビルドしない。`--build` フラグをつけるか、事前に `docker compose build` を実行する（#17 のキャッシュ最適化により再ビルドは数秒）。`docker compose up -d app` の場合も同様に `--build` をつける。
- **`git clone failed ... could not read Username`:** private リポジトリには `GITHUB_TOKEN` が必要。
- **API レート制限:** `GITHUB_TOKEN` を設定すると上限が大きく緩和される。
