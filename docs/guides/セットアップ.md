# セットアップ

## 前提

- Docker / Docker Compose
- （非公開リポジトリを索引する場合）リポジトリ読み取り権限のある GitHub トークン

## 手順

```bash
git clone https://github.com/masuda-masuo/shiori.git
cd shiori
cp .env.example .env
# .env を編集:
#   SHIORI_REPOS=owner/name      （カンマ区切りで複数可）
#   GITHUB_TOKEN=ghp_xxx         （公開リポジトリのみなら空でも可）

# DB と MCP サーバーを起動（初回はイメージビルド）
docker compose up -d --build

# 索引を作成（初回は埋め込みモデルのダウンロードを含むため時間がかかる）
docker compose run --rm app python -m shiori ingest
```

2 回目以降の `ingest` は差分同期（docs はファイルハッシュ、issue/PR は `updated_at` カーソル）なので速い。

## 索引の更新（4 経路）

| 経路 | 用途 |
| --- | --- |
| self-hosted runner | push / issue / PR のイベント発火で即時差分同期（主経路）。数十秒以内に反映。 |
| `SHIORI_SYNC_INTERVAL_SECONDS` | serve プロセス内のバックグラウンド自動同期（取りこぼし対策の保険）。推奨 3600（1 時間）。 |
| MCP ツール `shiori_ingest` | エージェント／ユーザーによるオンデマンド更新（「直近の変更がヒットしない」と思ったとき） |
| CLI `python -m shiori ingest` | 初回構築・cron 等のスケジュール実行 |

mcp-launcher 等で短命トークンを `GITHUB_TOKEN` として注入する構成では、自動同期と `shiori_ingest` ツールが serve プロセス内で実行されるため、長期トークンを別途用意する必要がない（issue #2）。

runner とその他の経路が同時に実行された場合は PostgreSQL advisory lock により片方が `skipped` になり、索引が壊れることはない（issue #6）。

## self-hosted runner の初回登録

### 1. 登録トークンを取得

GitHub のリポジトリページ → **Settings** → **Actions** → **Runners** → **New self-hosted runner** を開き、表示される登録トークンをコピーする（有効期限 1 時間）。

### 2. runner を登録

```bash
docker compose run --rm runner ./config.sh \
  --url https://github.com/masuda-masuo/shiori \
  --token <登録トークン> \
  --name shiori-runner \
  --labels shiori \
  --unattended \
  --disableupdate
```

登録状態（`.runner` / `.credentials`）は `runner-state` volume に永続化されるため、コンテナを再起動・再ビルドしても再登録は不要。

### 3. runner を起動

```bash
docker compose up -d runner
```

### 動作確認

リポジトリの issue を編集し、数十秒後に `shiori_semantic_search` や `shiori_read_issue` で変更が反映されていることを確認する。GitHub の **Actions** タブで `reindex` ワークフローの実行ログも確認できる。

### セキュリティ注意

**このリポジトリを public にする場合、self-hosted runner 構成は廃止すること。**
fork PR がワークフロー定義ごと差し替えてホスト上で任意コードを実行できるため。
public 化する場合の代替は Webhook + Cloudflare Tunnel + HMAC 署名検証。

## 埋め込みモデルの変更

埋め込みモデルを変更した場合は全件再索引する:

```bash
docker compose run --rm app python -m shiori ingest --rebuild
```

（MCP ツールからは `shiori_ingest(rebuild=true)`）

## MCP クライアントからの接続

MCP サーバーは streamable HTTP で `http://localhost:8765/mcp` に公開される。

例: Claude Code

```bash
claude mcp add --transport http shiori http://localhost:8765/mcp
```

コンテナを使わずローカルの Python で stdio 接続したい場合:

```bash
pip install -e .
DATABASE_URL=postgresql://shiori:shiori@localhost:5432/shiori \
  python -m shiori serve --transport stdio
```

（compose の `db` は 127.0.0.1:5432 に公開済み。Windows ホストの場合は
`SHIORI_DATA_DIR` にクローン先ディレクトリの指定が必要）

## 提供される MCP ツール

| ツール | 用途 |
| --- | --- |
| `shiori_semantic_search` | 意味検索（内部でハイブリッド）。まずこれを使う |
| `shiori_keyword_search` | 固有名詞・API 名・エラーコード等の厳密一致 |
| `shiori_list_tree` | 索引済みドキュメントのパス一覧 |
| `shiori_read_file` | ファイル全文（または行範囲）の取得 |
| `shiori_read_issue` | issue / PR スレッド全体の取得 |
| `shiori_ingest` | 索引の差分更新（`rebuild=true` で全件作り直し） |

## トラブルシューティング

- **`EMBEDDING_DIM=... but model produces ...`:** モデルと次元の組み合わせが不一致。`.env` の `EMBEDDING_DIM` をモデルの次元に合わせ、`ingest --rebuild` を実行。
- **検索が 0 件:** `ingest` が完了しているか、`SHIORI_REPOS` が正しいかを確認。
- **`git clone failed ... could not read Username`:** private リポジトリには `GITHUB_TOKEN` が必要。
- **API レート制限:** `GITHUB_TOKEN` を設定すると上限が大きく緩和される。
- **runner が起動しない（`.runner` なし）:** 上記「初回登録」手順を実行していない。`docker compose run --rm runner` を実行すると登録コマンドが表示される。
- **runner ジョブが skipped になる:** serve の自動同期と競合した場合の正常動作（advisory lock）。索引は壊れていない。
