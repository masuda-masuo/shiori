# 詳細設計: クローン管理と連携

> issue #89 対応。Shiori が管理する git clone を外部ツール（code-sandbox-mcp 等）から利用するためのパス規約と前提条件を定義する。

## 目的

Shiori は `sync_docs` でリポジトリのクローンを `--depth=1` で維持している。この既存クローンを sandbox コンテナや他のツールから直接コピー (`cp -r`) することで、ネットワーク越しの `git clone` をバイパスし、開発フローの起動を高速化する。

## クローンルートのパス規約

クローンは以下のパスに配置される:

```
{SHIORI_DATA_DIR}/repos/{owner}__{name}
```

- `{SHIORI_DATA_DIR}`: 環境変数 `SHIORI_DATA_DIR` の値（既定 `/data`）
- `{owner}__{name}`: リポジトリの owner と name を二重アンダースコアで連結
  - 例: `masuda-masuo__shiori`、`masuda-masuo__code-sandbox-mcp`
- 実装: `config.py::Settings.repo_dir()` (`src/shiori/config.py:122`)

パス区切りに `/` を使わず `__` を使うのは、owner/name に由来しないディレクトリ深度を持たせないため。

### 例

| `SHIORI_DATA_DIR` | repo | クローン先 |
|---|---|---|
| `/data` | `masuda-masuo/shiori` | `/data/repos/masuda-masuo__shiori` |
| `/data` | `masuda-masuo/code-sandbox-mcp` | `/data/repos/masuda-masuo__code-sandbox-mcp` |
| `/var/shiori` | `org/foo` | `/var/shiori/repos/org__foo` |

## クローンの管理

`sync_docs` (`src/shiori/github_sync.py`) が以下を実行する:

- **初回:** `git clone --depth=1 {remote} {repo_dir}`
- **更新:** `git fetch --depth=1 origin` → `git reset --hard origin/HEAD`
- **認証:** `http.extraHeader` でトークン注入（`_auth_args()`）

## 前提と制約

### depth=1 shallow clone

Shiori は `--depth=1` の shallow clone を維持する。履歴を持たないため以下が不可能:

- 過去コミットの参照 (`git log` で 1 commit のみ)
- merge-base の計算
- 通常の `git push`（push 先に履歴がないと reject される）
- 通常の `git checkout`（他のブランチを辿れない）

sandbox コンテナへのコピー後、`git fetch --unshallow` で履歴を補充すればこれらの制約は解消される。

### 鮮度

Shiori の auto-sync は既定で無効（`SHIORI_SYNC_INTERVAL_SECONDS=0`）。
クローンの最終更新時刻は `shiori_status()` の `last_synced_at` で確認できる。

クローンをコピーする側は「コピー時点のスナップショットが最新とは限らない」ことを前提とし、必要に応じて事前に `shiori_ingest()` で同期してからコピーすること。

### allowlist による制限

`SHIORI_REPOS` 環境変数で許可されたリポジトリのみ同期可能。
`shiori_ingest` は指定された `repo` が `SHIORI_REPOS` に含まれているかを検証し、
含まれないものは拒否する（`src/shiori/ingest.py::_validate_repos_allowlist`）。

クローンを利用する外部ツールも、この allowlist と同じ制約を尊重する
（パストラバーサル対策として `${SHIORI_DATA_DIR}/repos/` 配下以外のパスを
読み取らないこと）。

## 外部ツールとの連携

### code-sandbox-mcp

`sandbox_initialize(clone_repo="masuda-masuo/shiori")` または
`run_container_and_exec(clone_repo="masuda-masuo/shiori")` を指定すると、
ホスト側の `${SHIORI_DATA_DIR}/repos/{owner}__{name}` からコンテナ内に
`cp -r` でコピーされる（ネットワーク越しの `git clone` をバイパス）。

code-sandbox-mcp は `--shiori-repos-path` サーバーオプションで
`SHIORI_DATA_DIR/repos` のパスを設定する（実装:
`src/code_sandbox_mcp/tools/container.py::_clone_shiori_repo_to_container`）。

### 他のツール

同様の規約に従い、`{SHIORI_DATA_DIR}/repos/{owner}__{name}` をコピー元とすることで
任意のツールが Shiori のクローンを再利用できる。
