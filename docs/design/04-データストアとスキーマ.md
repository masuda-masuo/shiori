# 詳細設計: データストアとスキーマ

## 目的

ベクトル・全文・メタデータを単一の PostgreSQL に統合し、ハイブリッド検索とフィルタを SQL で完結させる。

## 採用技術

- **PostgreSQL**
- **pgvector:** 埋め込みの格納とベクトル類似度検索（コサイン等）。
- **pgroonga または pg_bigm:** 日本語対応の全文検索（キーワード）。
- **構造化列:** メタデータ（`repo`, `path`, `source_type`, `language`, `state`, 日付, 番号 等）。

## 設計の利点

- 1 つの DB でベクトル＋全文＋メタデータを扱える。
- ハイブリッドの融合（例: RRF）と、メタデータのフィルタ（`WHERE` 句）を同一クエリで実行できる。別システム間の同期・結果融合を自前で持たずに済む。

## スキーマ（暫定イメージ）

```
chunks(
  id, source_type, repo, path, issue_no,
  language, heading_path, content,
  embedding vector, state, author,
  created_at, updated_at, url
)
```

全文索引は `content` に対して pgroonga/pg_bigm の索引を張る。

## 検討事項 / 未決

- 全文拡張: **pgroonga**（日本語スコアリングが豊富） vs **pg_bigm**（軽量・bigram ベース）。
- docs 用と issue/PR 用でテーブル（コレクション）を分けるか、`source_type` 列で 1 テーブルに統合するか。
- Docker イメージ: 素の postgres には pgvector/pgroonga が入らないため、両方入りのイメージを compose の build で用意する。
