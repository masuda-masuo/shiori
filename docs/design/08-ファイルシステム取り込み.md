# 詳細設計: ファイルシステム取り込み（fs ソース）

## 目的

Git / GitHub に依存しないローカルディレクトリ（メモ、Obsidian vault、生成 AI の成果物等）を
docs と同じパイプライン（チャンク → 埋め込み → 索引 → 検索）に乗せる。

設計方針: **`01` の取り込み層に第三の経路 `fs` を追加するだけ**とし、
チャンク（`02`）・埋め込み（`03`）・スキーマ（`04`）・検索（`05`）は無改修で流用する。

## 決定事項

1. **ソースの識別子は `fs:{name}` を `repo` 列に格納する。**
   GitHub リポジトリは必ず `owner/name` 形式（`/` を含む）、fs の `name` は `/` を禁止するため衝突しない。
   `fs:` プレフィックスにより検索フィルタ・削除・再構築で経路を区別できる。
2. **`source_type` は `doc` のまま。** fs のファイルは意味的にドキュメントであり、
   検索側のフィルタ（doc / issue / pr_review）を変えない。
3. **差分検出は既存の `doc_files`（sha256 コンテンツハッシュ）方式をそのまま使う。**
   `doc_files.repo` に `fs:{name}` を入れる。スキーマ変更なし。
4. **`url` は `file://` スキームで「設定されたルートパス＋相対パス」を格納する。**
   コンテナ内パスとホストパスが異なる問題は `url_base` 設定で吸収する（後述）。
5. **`sync_state` カーソルは使わない**（git HEAD に相当するものがないため）。
6. **既存 `sync_docs` との共通化のため、走査〜索引のロジックを `doc_indexer.py` に抽出する**
   （リファクタリング。挙動は変えない）。

## 設定（環境変数）

| 変数 | 必須 | 例 | 説明 |
| --- | --- | --- | --- |
| `SHIORI_FS_SOURCES` | fs を使う場合のみ | `notes=/data/notes;specs=/data/specs` | `name=path` を `;` 区切りで列挙 |
| `SHIORI_FS_INCLUDE_EXTS` | 任意 | `.md,.mdx,.markdown` | 対象拡張子（小文字、`,` 区切り）。既定は左の 3 つ |
| `SHIORI_FS_EXCLUDE_DIRS` | 任意 | `.git,node_modules,.obsidian` | 走査から除外するディレクトリ名（`,` 区切り）。既定は左の 3 つ |
| `SHIORI_FS_URL_BASE` | 任意 | `notes=file:///Users/me/notes` | `name=base` 形式。`url` 列の組み立てに使う。未指定の name はコンテナ内パスで `file://{path}` |

`Settings`（`src/shiori/config.py`）への追加:

```python
@property
def fs_sources(self) -> dict[str, str]:
    """{name: root_path}。SHIORI_FS_SOURCES を ';' と '=' で分解する。"""
    raw = os.environ.get("SHIORI_FS_SOURCES", "")
    out: dict[str, str] = {}
    for pair in filter(None, (p.strip() for p in raw.split(";"))):
        name, _, path = pair.partition("=")
        name, path = name.strip(), path.strip()
        if not re.fullmatch(r"[A-Za-z0-9_-]+", name):
            raise ValueError(f"invalid fs source name: {name!r} (use [A-Za-z0-9_-])")
        if not path:
            raise ValueError(f"fs source {name!r} has empty path")
        out[name] = path
    return out
```

`fs_include_exts`（tuple、既定 `(".md", ".mdx", ".markdown")`）、
`fs_exclude_dirs`（set、既定 `{".git", "node_modules", ".obsidian"}`）、
`fs_url_bases`（dict）も同様のパース関数で追加する。

## 実装

### 1. 共通モジュール `src/shiori/doc_indexer.py`（新規）

`github_sync.sync_docs` の 92〜164 行目（走査〜索引）を移設・一般化する。

```python
from collections.abc import Callable

def index_doc_tree(
    settings: Settings,
    conn: psycopg.Connection,
    embedder: Embedder,
    *,
    repo_key: str,                      # 例: "owner/name" または "fs:notes"
    root_dir: str,                      # 走査ルート（絶対パス）
    url_for: Callable[[str, str], str], # (rel_path, anchor) -> url
    include_exts: tuple[str, ...],
    exclude_dirs: set[str],
) -> int:
    """root_dir 配下を走査し、差分のあるファイルだけ再索引する。返り値は更新+削除ファイル数。"""
```

アルゴリズム（現行 `sync_docs` と同一。差分のみ注記）:

1. `os.walk(root_dir)`（`followlinks=False`）で再帰走査。
   `dirs[:] = [d for d in dirs if d not in exclude_dirs]` で除外（現行は `.git` 固定 → 引数化）。
   拡張子判定は `f.lower().endswith(include_exts)`（現行のハードコード → 引数化）。
   `current[rel] = sha256(file bytes)` を構築。
2. `doc_files` から `repo = repo_key` の `{path: content_sha}` を取得し、
   `removed = indexed - current`、`changed = [p for p in current if indexed.get(p) != sha]`。
3. `removed` は `delete_chunks_by_key(conn, f"doc:{repo_key}:{path}")` と `doc_files` 行削除。
4. `changed` は読み込み（`encoding="utf-8", errors="replace"`）→ `detect_language` →
   `split_markdown` → `delete_chunks_by_key` → `embed_passages` → `insert_chunk`。
   `insert_chunk` の引数は現行どおり（`source_type="doc"`, `repo=repo_key`, `path=rel`,
   `url=url_for(rel, anchor)`）。anchor の組み立ても現行ロジック（heading_path 末尾を
   lower + 空白→`-`）を関数内に保持する。
5. ファイルごとに `doc_files` を UPSERT し `conn.commit()`。

### 2. `src/shiori/fs_sync.py`（新規）

```python
def sync_fs(
    settings: Settings, conn: psycopg.Connection, embedder: Embedder,
    name: str, root: str,
) -> int:
    if not os.path.isdir(root):
        raise RuntimeError(
            f"fs source {name!r}: directory not found: {root}"
            "（compose の volumes でマウントされているか確認してください）"
        )
    base = settings.fs_url_bases.get(name, f"file://{root.rstrip('/')}")

    def url_for(rel: str, anchor: str) -> str:
        return f"{base}/{rel}{anchor}"

    return index_doc_tree(
        settings, conn, embedder,
        repo_key=f"fs:{name}", root_dir=root, url_for=url_for,
        include_exts=settings.fs_include_exts,
        exclude_dirs=settings.fs_exclude_dirs,
    )
```

git 操作（clone / fetch / reset / rev-parse、79〜90・118〜120 行目）と
`set_cursor(conn, repo, "docs", head)` は残し、走査〜索引部分を次の呼び出しに置換する:

```python
def url_for(rel: str, anchor: str) -> str:
    return f"https://github.com/{repo}/blob/{default_branch}/{rel}{anchor}"

n = index_doc_tree(
    settings, conn, embedder,
    repo_key=repo, root_dir=repo_dir, url_for=url_for,
    include_exts=(".md", ".mdx", ".markdown"),
    exclude_dirs={".git"},

```

**リファクタリング後の回帰確認:** 既存リポジトリで `ingest` を実行し、
`chunks` / `doc_files` の行数・`content_sha` が変化しないこと（差分ゼロで no-op になること）。

### 4. CLI（`python -m shiori ingest`）

- 既定動作: 設定済みの GitHub リポジトリ全件 → fs ソース全件の順に同期する。
- `--source <key>` を追加: `owner/name` または `fs:name` を指定して 1 ソースのみ同期。
- `--rebuild` は fs ソースにも適用（`repo = 'fs:{name}'` の `chunks` と `doc_files` を
  DELETE してから全ファイルを changed 扱いで再索引）。

### 5. MCP サーバー側の変更（`mcp_server.py`）

`list_tree` / `read_file` がソースのルートを解決できるようにする。

```python
def resolve_root(settings: Settings, repo_key: str) -> str:
    if repo_key.startswith("fs:"):
        name = repo_key[3:]
        try:
            return settings.fs_sources[name]
        except KeyError:
            raise ValueError(f"unknown fs source: {name}")
    return settings.repo_dir(repo_key)
```

- 両ツールに `repo` 引数（任意）を追加。省略時は現行の既定リポジトリ。
- **パストラバーサル防止（必須）:** 解決後に
  `os.path.realpath(joined).startswith(os.path.realpath(root) + os.sep)` を検証し、
  違反は `ValueError("path escapes source root")`。
- ツール description に「fs ソースは `repo="fs:{name}"` で指定する」と明記する。

### 6. Docker Compose

fs ソースは **read-only でマウント**する。ingest 実行時の例:

```yaml
services:
  app:
    volumes:
      - /Users/me/notes:/data/notes:ro
```

`SHIORI_FS_SOURCES=notes=/data/notes`、
`SHIORI_FS_URL_BASE=notes=file:///Users/me/notes` を `app` の environment に追加。

## エッジケース

- **シンボリックリンク:** ディレクトリは辿らない（`followlinks=False`）。ファイルの
  シンボリックリンクは通常ファイルとして読む。読み取り失敗（リンク切れ等）は
  そのファイルを warning ログでスキップし、処理を継続する。
- **読めないファイル:** `OSError` は warning でスキップ（1 ファイルの失敗で
  ingest 全体を落とさない）。
- **空ディレクトリ / 全削除:** `current` が空でも正常系。既存索引は `removed` として
  全削除される（リポジトリ側と同じ挙動）。
- **name の重複:** `SHIORI_FS_SOURCES` 内の重複 name は起動時に `ValueError`。
- **巨大ファイル:** 1 ファイル 10MB 超は warning でスキップ（誤マウント対策。
  しきい値は `SHIORI_FS_MAX_FILE_BYTES`、既定 10_485_760）。

## テスト項目

1. `fs_sources` パース: 正常 / name 不正 / path 空 / 重複 name。
2. `index_doc_tree`: 新規→全件索引、変更 1 件→1 件のみ再索引、削除→索引消滅、
   exclude_dirs 配下が無視される、include_exts 外が無視される。
3. `sync_fs`: ルート不在で RuntimeError、`url` が `url_base` 設定で期待値になる。
4. リファクタリング回帰: 既存 GitHub リポジトリの再 ingest が no-op。
5. `read_file` / `list_tree`: `fs:` 解決、`../` でのトラバーサル拒否。
