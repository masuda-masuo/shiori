# 詳細設計: 実行環境とデプロイ

## 目的

ホストを汚さず、再現性のある形で DB と MCP サーバーを動かす。

## 構成: Docker Compose（2 常駐サービス + 2 opt-in）

- `db`: PostgreSQL（pgvector + pgroonga/pg_bigm 入りイメージ）。常駐。
- `app`: MCP サーバー（自作コード）。常駐。
- `runner`（profiles: ["runner"]）: self-hosted GitHub Actions runner（issue #6）。push / issue / PR イベントで即時差分同期。opt-in（issue #15）。
- `ingest`（profiles: ["ingest"]）: オンデマンドの使い捨て同期ジョブ。opt-in。
- **分離する理由:** app を再ビルド／再起動しても DB を巻き込まない（索引の再構築回避）、コンテナの 1 プロセス原則（PID1）に沿う、DB は公式系イメージを活用。

## 永続化

- DB のデータディレクトリは **named volume** に置く（コンテナの書き込みレイヤーに置くと再ビルドで消え、埋め込みを作り直す羽目になる）。
- 埋め込みモデルの重みも volume にキャッシュ。
- runner の登録状態（`.runner` / `.credentials`）は `runner-state` volume に永続化（再起動・再ビルドで再登録不要）。

## 起動

- `docker compose up -d` で db + app が立ち上がる（runner は profiles: ["runner"] のため起動しない。issue #15）。
- runner を有効にするには `COMPOSE_PROFILES=runner` を `.env` に設定するか、`--profile runner` を付与する。
- runner は初回のみ `docker compose run --rm runner ./config.sh ...` で登録が必要（セットアップ.md 参照）。

## ingest（同期）の方針（issue #6 で決定、issue #15 で補強）

4 経路で索引を最新に保つ:

1. **self-hosted runner**（主経路）: push / issue / PR のイベントを GitHub からアウトバウンド（ロングポーリング）で受け取り、即時差分同期。inbound ポート開放・Webhook・トンネル不要。数十秒以内に反映。
2. **SHIORI_SYNC_INTERVAL_SECONDS**（保険）: serve プロセス内の自動同期。runner あり: 3600 秒推奨。
3. **MCP ツール `ingest`**（オンデマンド）: エージェント／ユーザーが「直近の変更がヒットしない」と感じたとき。
4. **CLI `python -m shiori ingest`**（初回・cron）: 初回構築やスケジュール実行。

複数経路が同時に走った場合は PostgreSQL advisory lock（`pg_try_advisory_lock`）で排他し、後発が `skipped` を返す。索引は壊れない。

**issue #15 で追加:**
- `runner` サービスに `profiles: ["runner"]` を付与し、起動を opt-in に変更。
- `reindex.yml` の `ingest` ジョブに `if: github.event.repository.private == true` を追加。リポジトリが public 化された時点でワークフロー側が自動停止する。
- public 化手順: プロファイル無効化 → `config.sh remove` → ワークフロー自動停止（ガード）。

## セキュリティ（runner）

**このリポジトリを public にする場合、self-hosted runner 構成（`runner` サービス・`reindex.yml`）を無効化すること**: `.env` から `COMPOSE_PROFILES=runner` を削除し、`config.sh remove` で runner 登録を解除する。
fork PR がワークフロー定義ごと差し替えてホスト上で任意コードを実行できるため、public リポジトリでは self-hosted runner を使用しない。
`reindex.yml` の `if: github.event.repository.private == true` ガード（issue #15）は public 化時にジョブを自動スキップする保険だが、根本対策ではない（runner の登録が残っていればリスクの根は残るため、上記の登録解除まで行うこと）。
public 化する場合の代替は Webhook + Cloudflare Tunnel + HMAC 署名検証。

認証の方針は詳細設計/09 の決定を踏襲する: GitHub App 秘密鍵は ingest 系（ingest ワンショットコンテナ・runner コンテナ）にのみ渡し、常駐 app には渡さない。runner ジョブはコンテナ内で直接 `python -m shiori ingest` を実行するため、ワークフロー内に secrets は登場せず、長期トークンも不要。
