# 詳細設計: チャンク戦略

## 目的

検索単位（チャンク）を、ソースの構造に合わせて適切に切り出す。文脈を保ちつつ、過不足ないサイズにする。

## ドキュメント（Markdown）

- 見出し（`#`, `##`）単位で分割（構造を保持 → 検索精度向上）。
- 見出しパス（例: `設計 > 認証 > トークン`）をメタデータに保持し、チャンク単体でも文脈が分かるようにする。
- 長い節は文字数だけで切らない。日本語は文・単語の途中で切れやすいので、句点・文単位の分割を併用する。

## issue / PR（会話的構造）

- 見出し単位は効かない。自然な単位は「スレッド」または「コメント 1 件」。
- issue のタイトル＋本文を文脈として保持しつつ、コメントをチャンク化。
- PR レビューコメントは特定のファイル・行（差分）に紐づくため、周辺コードを文脈として持たせる。

## 言語の扱い

- ファイル単位で言語は統一されている前提。チャンクごとに `language` を一度タグ付けし、キーワード検索のアナライザ切り替え・絞り込みに使う。

## 検討事項 / 未決

- issue スレッドを**生のまま索引するか、取り込み時に「何が解決したか」の要約を生成して併せて索引するか**（精度↑ / 取り込みコスト↑）。
- チャンクサイズ（トークン基準 vs 文字基準。日本語はトークン消費が異なる）。
- 隣接チャンクの取得（前後参照）。
