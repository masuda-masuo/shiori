# 詳細設計: チャンク戦略

## 目的

検索単位（チャンク）を、ソースの構造に合わせて適切に切り出す。文脈を保ちつつ、過不足ないサイズにする。

## ドキュメント（Markdown）

- 見出し（`#`, `##`）単位で分割（構造を保持 → 検索精度向上）。
- 見出しパス（例: `設計 > 認証 > トークン`）をメタデータに保持し、チャンク単体でも文脈が分かるようにする。
- 長い節は文字数だけで切らない。日本語は文・単語の途中で切れやすいので、句点・文単位の分割を併用する。

## issue / PR（会話的構造）

- 見出し単位は効かない。自然な単位は「スレッド」または「コメント 1 件」。
- issue のタイトル＋本文を文脈として保持しつつ、コメントをチャンク化。
- PR レビューコメントは特定のファイル・行（差分）に紐づくため、周辺コードを文脈として持たせる。

## 言語の扱い

- ファイル単位で言語は統一されている前提。チャンクごとに `language` を一度タグ付けし、キーワード検索のアナライザ切り替え・絞り込みに使う。

## 決定（v1 実装, 2026-06）

- **issue スレッドは生のまま索引する**（要約生成は v1 では行わない）。理由: 要約には LLM 呼び出しが必要で、取り込みコスト・再現性・「ローカル完結」の原則と衝突する。チャンク単位は「コメント 1 件」とし、全チャンクに issue/PR タイトルを `[タイトル]` プレフィックスとして付与して単体でも文脈が分かるようにする。
- **チャンクサイズは文字基準で最大 1200 字**（`SHIORI_CHUNK_MAX_CHARS` で変更可）。トークン基準は埋め込みモデルのトークナイザに依存し可搬性が下がるため不採用。分割は文境界（`。．！？!?.` と空行）を優先し、超過する単一文（コードブロック等）のみ機械的に切る。
- **見出しパスはメタデータ＋本文プレフィックスの両方に保持。** チャンク本文先頭に `[親 > 子]` の 1 行を付け、埋め込み・キーワード両方の検索に文脈を効かせる。コードフェンス内の `#` は見出しとして扱わない。
- **言語判定はヒューリスティック:** 日本語文字（ひらがな・カタカナ・漢字）が文字種全体の 20% 以上なら `ja`、それ以外は `en`。
- **隣接チャンクの取得は専用機能を持たない。** doc は `read_file(path, range)` で前後を読める。issue は `read_issue` でスレッド全体を取れる。
