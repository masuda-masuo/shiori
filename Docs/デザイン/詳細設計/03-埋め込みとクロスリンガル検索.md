# 詳細設計: 埋め込みとクロスリンガル検索

## 目的

意味検索（semantic search）のための埋め込みを、日英混在・ローカル実行の制約下で設計する。

## モデル選定の方針

- 多言語、できれば**クロスリンガル対応**の埋め込みを選ぶ。
- クロスリンガルが必要な理由: クエリは主に日本語、公開ドキュメントは英語。言語の壁は「クエリとコーパスの間」に残る。日本語クエリで英語ドキュメントを引けることが価値になる。
- 候補: BGE-m3、multilingual-e5(large) など、日英を共通ベクトル空間に寄せるもの。
- 選定は**自分の JA/EN データで実際に検索精度を測って**決める（言語ペアで品質が変わるため）。

## 実行環境

- ローカル実行（非公開データを外部に出さない）。
- モデルの重み（数百 MB 〜）は named volume にキャッシュし、再ビルドで再ダウンロードしない。

## 検討事項 / 未決

- 埋め込み次元とインデックス（pgvector の HNSW 等）の設定。
- バッチ埋め込みによる取り込み高速化。
- リランクモデル（詳細は `05-検索とハイブリッド検索` を参照）。
